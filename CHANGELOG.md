# Changelog

All notable changes to this project are documented in this file. The format is
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the project adheres
to [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

Entries from 1.1.0 through 2.1.1 were generated by semantic-release from commit
messages and keep that tool's section names; from 3.0.0 the changelog is
hand-maintained and releases are published manually (see README "Releasing").
Unreleased changes accumulate under `[Unreleased]` and move under a version
heading at release time.

## [Unreleased]

### Added

- **Cost assessment.** `openai-img cost --start <time> [--end <time>] [--project-id …] [--api-key-id …] [--json] [--output <file>]`
  and `OpenAIAdminAPI.assessImageCosts(range, filters)` reconcile the organization
  Images-usage endpoint (activity counts) with the Costs endpoint (amounts) per
  UTC day and scope. Needs an admin key in `OPENAI_ADMIN_KEY`. Attribution is
  conservative by construction: a cost row is image spend only when its
  `quantity_unit` is `images` or its `line_item` is in a versioned exact-match
  list; scopes join only on known, equal project + API-key ids; amounts are
  integer micro-units per currency; every row carries its attribution level,
  warnings, raw line items, an image breakdown and provenance. Pure algorithm at
  `openai-image-api/cost`, paginating client at `openai-image-api/admin`,
  `OpenAIImageAPIError` also at `openai-image-api/errors`. Spec:
  `docs/openai-image-cost-assessment-spec.md`.

### Fixed

- **`logLevel: 'WARNING'` silenced every log line, errors included.** winston
  has no `warning` level; assigning it muted the transport. The value has been
  documented since 1.0 and became the library default in 3.0.0, so 3.0.0's
  deprecation warnings and error logs never reached stdout. Level names are
  now mapped (`WARNING` → `warn`) through one function and an unknown name
  throws instead of muting. Tests assert on transport output, not on spies.

## [3.0.0] - 2026-09-21

The 3.0.0 line tracks what OpenAI removed or shipped in the Image API during
2026. Every removal below corresponds to an API that no longer exists or has an
announced shutdown; nothing was removed on this package's own initiative.
Migration table: README "Migrating from 2.x".

### Added

- Models `gpt-image-2.5-sunburst`, `gpt-image-2.5-flare` (new default), `gpt-image-2`
  and `gpt-image-1-mini`, plus the dated snapshots `gpt-image-2.5-sunburst-2026-09-08`,
  `gpt-image-2.5-flare-2026-09-08` and `gpt-image-2-2026-04-21` as aliases that
  validate with their family's constraints.
- Free-form `WIDTHxHEIGHT` sizes for gpt-image-2 and the 2.5 models (edges
  divisible by 16, aspect ratio 1:3–3:1, no edge above 3840 px, 655,360–8,294,400
  pixels); `xhigh` and `max` quality on the 2.5 models.
- Streaming with partial images: `streamImage()` / `streamImageEdit()` async
  generators, `generateImageStream()` / `generateImageEditStream()` callback
  wrappers, an SSE parser in `utils`, and CLI `--stream --partial-images N`.
  Partial frames are saved beside the final image and listed in the metadata
  sidecar. (2.1.0 announced this feature; only a constraints entry shipped.)
- `OpenAIImageAPIError` thrown for every failure from the API class: `status`,
  `code`, `type` and `apiMessage` from the API's error body, or the package's
  own `type` — `validation_error`, `input_error`, `configuration_error`,
  `stream_error` — for failures before a request is sent; `cause` carries the
  original error.
- `validateRequest(params)`: the full pre-flight (key, prompt, constraint
  table, input files opened and header-checked) without sending. `--dry-run`
  calls it.
- `APIOptions.skipValidation` / CLI `--no-validate`: send an id or parameter
  the constraint tables do not know and let the API judge. The tables are a
  dated transcription of OpenAI's reference; this is the path past them when
  OpenAI moves first.
- `APIOptions.requestTimeout` (default 180 s). Deprecation warnings, once per
  model per instance, for `gpt-image-1` (shutdown 2026-10-23), `gpt-image-1.5`
  and `gpt-image-1-mini` (2026-12-01); tense-aware after the date.
- `npm run check:reference`: diffs model ids, quality tiers, size rules and
  shutdown dates in `src/config.ts` against OpenAI's published reference.
- `OPENAI_IMAGE_API_NO_DOTENV` opt-out for library consumers who manage their
  own configuration.
- ESLint (type-aware) and Prettier; `npm run lint`, `format:check`, `verify`.
  CI runs on pull requests as well as pushes to `main`. `src/` is published so
  the shipped source maps resolve.

### Changed

- **Default model is `gpt-image-2.5-flare`** (was `dall-e-2`, which has returned
  404 since 2026-05-12). Cost note: a pipeline that upgrades with no `--quality`
  now pays GPT Image 2.5 `auto`-quality rates.
- **Library log level defaults to `WARNING`** (was `INFO`): constructing the
  class and making requests no longer writes progress lines to the host's
  stdout. The CLI is unchanged (`--log-level`, default INFO).
- Every throw from `OpenAIImageAPI` — including the constructor's non-HTTPS
  `baseUrl` check — is an `OpenAIImageAPIError`. Messages are unchanged from
  2.x, so `catch` on message text still works; `instanceof` now covers all of
  them.
- `.env` files are read lazily, only when a key is actually looked up (no
  `apiKey` passed and `OPENAI_API_KEY` unset), not at import time. The CLI
  still loads them up front.
- Edits open each input once, check size (≤ 50 MB) and magic bytes
  (PNG/JPEG/WebP; GIF is not an API input format), and upload from that same
  open handle with an explicit multipart filename, content type and length.
  Files are opened after the rate-limit wait, not held across it.
- Rate limiting is serialized across concurrent calls on one instance; 2.x
  spaced only sequential callers and released concurrent ones as a burst.
- Output filenames: `YYYY-MM-DD_HH-MM-SS-mmm_<4 hex>_<model>_<prompt>` — millisecond
  resolution plus a nonce so parallel runs do not overwrite; the prompt stem
  keeps letters and digits in any script (a Japanese prompt keeps its
  characters) and Windows-reserved stems get a trailing `_`. Output
  directories use the full model id (`datasets/openai/gpt-image-2.5-flare/`).
- `saveImages` validates `outputDir` (no `..` segment) and requires
  `baseFilename` to be a single path component; `format` is optional and
  defaults to the response's `output_format`.
- `--api-key` prints a warning about process-list visibility on shared hosts;
  the missing-key message lists the environment variable and constructor option
  before the CLI flag.
- A `--prompt` batch with any failed prompt exits 1 and lists the failures;
  2.x printed the success banner and exited 0 even when every prompt failed.
  `process.exit` waits for the logger to flush.
- Error messages for timeouts name `requestTimeout` and its current value;
  connection failures name the unreachable `baseUrl`. Under
  `NODE_ENV=production` the CLI appends the API's own reason and code in
  parentheses; the library keeps it on `apiMessage`, deliberately exempt from
  sanitization (it is addressed to the key holder).
- `package.json` description leads with what the package does; `main` is the
  default branch; the 1.0.0 changelog link pointed at a misspelt repository.
- CLI logic moved to `src/cli-core.ts` (unit-tested in-process); `src/cli.ts`
  is the bin entry. Not a public entry point.

### Removed

- **DALL-E 2 and DALL-E 3.** Shut down by OpenAI on 2026-05-12 (live 404
  confirmed 2026-09-20). With them: `generateImageVariation()` and `--variation`
  (`/v1/images/variations` was DALL-E-2-only), `response_format`, `style`, and
  `url` in responses (GPT Image models always return base64), and the
  `--dalle-2` / `--dalle-3` flags.
- **Sora 2 and the Videos API.** OpenAI shutdown 2026-09-24. `OpenAIVideoAPI`,
  the `openai-image-api/video-api` export, `--video`, `--sora-2`, `--sora-2-pro`,
  `--remix-video`, `--list-videos`, `--delete-video`, `--seconds`,
  `--input-image`, `--variant`, and the video utilities.
- From `openai-image-api/utils`: `validateImageUrl`, `downloadImage`,
  `imageToBase64` (served the DALL-E URL-response path; the package performs
  no outbound fetch other than the API call, so the SSRF guard that protected
  those fetches went with them), `validateImageFile`, `pause`. From `types`:
  `RequestOptions`, `ImageFileConstraints`.
- semantic-release. Releases are published manually; see README "Releasing".

### Fixed

- `gpt-image-1.5` was broken since 2.1.0: its options were gated on
  `model === 'gpt-image-1'`, so requests carried `response_format` (a 400) and
  silently dropped `background`, `output_format`, `moderation` and
  `input_fidelity`; edits posted `image` instead of `image[]`. All GPT Image
  models share one code path.
- The 30 s request timeout added in 2.1.0 aborted ordinary high-quality
  generations (the guide states complex prompts can take up to two minutes).
- `--dry-run` printed "validated successfully" without validating (2.1.1), then
  ran only the constraint table (3.0.0 pre-release); it now runs the full
  pre-flight, so a missing prompt or a nonexistent `--image` fails dry-run
  exactly as the real call would.
- `input_fidelity` is rejected client-side for gpt-image-2 and both 2.5 models.
  The API reference documents the restriction for gpt-image-2 only; the live
  API returns 400 for Sunburst and Flare too (verified 2026-09-20).
- `n > 1` on a streaming request is refused: the wrappers return on the first
  completed event and would otherwise bill images this code never surfaces.
- Streaming: mid-body failures (idle timeout, reset) throw the same
  `OpenAIImageAPIError` vocabulary as pre-headers failures; the response
  stream is destroyed when the consumer breaks out early; events without
  `b64_json` are skipped; a mixed `\r\n\n` delimiter no longer eats the next
  event's first byte; the buffer is scanned from an offset rather than from
  byte 0 on every chunk.
- Buffered responses without a `data[]` array raise "Unexpected response
  shape" instead of a `TypeError`. `partial_images` is dropped from buffered
  requests. `validateFlexibleSize` names its expected argument when handed a
  model id.
- `validateOutputPath` rejects a `..` path *segment*, not the substring:
  `my..dir` is a legal name.
- `tsconfig.test.json` inherited `exclude: ["test"]`, so it had never
  type-checked a test file. Fixed; tests type-check under strict mode.

### Security

- `axios` ^1.20.0 and `form-data` ^4.0.6 (both reachable inside the previous
  ranges; the lockfile was behind). `npm audit --omit=dev`: 0.
- Multipart part filenames are set explicitly (basename with CR/LF/quote
  replaced), so a hostile `--image` path cannot inject headers regardless of
  the form-data version.
- Bounded buffers: a single SSE event is capped at 128 MiB and buffered
  responses at 256 MiB (`maxContentLength`/`maxBodyLength`) — far above any
  real image; they exist so a hostile or broken upstream cannot exhaust
  memory.
- `decodeBase64Image` and `writeToFile` refuse a `..` path segment; the SDK
  no longer exports an unvalidated file-write primitive.

## [1.0.0] - 2025-11-15

### Added
- Initial release of OpenAI Image Generation API wrapper
- Support for DALL-E 2, DALL-E 3, and GPT Image 1 models
- Three operation modes: generate, edit, variation
- Command-line interface with `openai-img` binary
- Comprehensive parameter validation for all models
- Batch processing support for multiple prompts
- Organized data storage with timestamped filenames and metadata
- Winston logging with configurable levels
- 128 comprehensive tests with Vitest
- Security features:
  - SSRF protection (blocks localhost, private IPs, cloud metadata endpoints)
  - File input validation with magic byte checking
  - Enhanced API key format validation (supports both sk-* and sk-proj-* formats)
  - HTTPS enforcement for API base URL
  - Rate limiting to prevent quota exhaustion
  - API key redaction in logs
  - Error message sanitization for production environments
- Detailed README with examples, troubleshooting, and model comparison
- API key configuration via multiple methods (CLI flag, env var, .env files)
- Support for all model-specific features:
  - DALL-E 2: Multiple images, variations, edits
  - DALL-E 3: HD quality, vivid/natural styles
  - GPT Image 1: Transparent backgrounds, multi-image editing, compression control

### Security
- Implemented SSRF protection to prevent access to internal resources
- Added file validation to ensure only valid image files are processed
- Enhanced API key format validation with regex patterns
- Enforced HTTPS-only connections to API endpoints
- Added rate limiting to prevent API abuse
- Implemented log sanitization to prevent API key exposure
- Added production-safe error messages to prevent information disclosure

### Documentation
- Comprehensive README with installation, usage, and examples
- API documentation for all public methods
- Troubleshooting guide with common errors and solutions
- Model comparison table
- Organization verification requirements for GPT Image 1
